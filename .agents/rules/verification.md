# 検証ルール

変更したファイルと挙動のリスクに応じて、適切な検証を選ぶこと。

- フロントエンドのTypeScript、コンポーネント、Hook、スタイル、設定を
  変更した後は `pnpm check` を実行すること。
- 実装作業の完了を報告する前に `git diff --check` を実行すること。
- 表示されるUI、レスポンシブ動作、操作部品を変更した場合は、ビルドに加えて
  ローカルアプリまたはブラウザで対象画面を確認すること。
- RustコードまたはTauri設定を変更した場合は、ローカル環境で実行可能な
  CargoまたはTauriの関連チェックを実行すること。
- 実行していない検証は明示すること。ビルドだけで操作上の挙動まで確認したと
  誤解させないこと。
